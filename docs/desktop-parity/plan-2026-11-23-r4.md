## 4. 建议的下一批（待你确认）

**推荐 E1：「审阅与撤销」（G1 + G2）**。理由：这是 OpenCode 最有辨识度的 harness 能力，也是 Agent 与 GUI 共享同一项目状态时最需要的安全网；它不改变租约语义，只在写入路径旁边增加一本「本轮改动账本」。

- 账本：每个 Agent 回合记录 `before`/`after` 文档快照（画布与时间线的 JSON，按工程版本号），写入只追加，回合结束封存。
- 撤销：按账本逆序回放「before」，经同一套带版本号的保存命令落地；若期间用户又改过同一节点，拒绝并给出冲突说明（不静默覆盖）。
- 审阅：按节点列出新增/修改/删除，可逐条「保留」或「撤回」。
- 完成定义：单元测试（账本封存、撤销、冲突拒绝、租约持有期间的并发）+ 沙箱真浏览器旅程（zh+en）+ 录屏 mp4 + windows-2022 装机冒烟；交付 `desktop16-review-undo.mp4`。
- 风险：触碰 `creation_projects.py` 写路径，属于数据安全红线，需先出设计说明再动代码。

备选：E2「历史多选回填」（G3，较小，可验证性高，适合作为首个快速交付）。
